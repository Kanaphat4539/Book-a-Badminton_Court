# ตรวจสอบแดชบอร์ดและรายงานการจอง

## ขอบเขตข้อมูล

- แดชบอร์ดผู้ดูแลอ่านรายการจาก `GET /bookings` และคำนวณตัวเลข/กราฟจากรายการที่ API ส่งกลับ ไม่มีข้อมูลตัวอย่างหรือค่าประมาณ
- ช่วงวันอิง `booking_date` ตามเวลา Asia/Bangkok; กราฟรายวันใช้ชั่วโมงจาก `time_in` และกราฟอื่นเรียงตามวัน/เดือน
- สถานะที่แสดง: `PENDING`, `CHECKED_IN`, `CANCELLED`, `COMPLETED`; READY_CHECK_IN หมายถึงรายการ PENDING ที่เข้าเงื่อนไขเวลาเช็กอินของบริการ
- ผู้ใช้ทั่วไปยังอ่านรายการของตนผ่าน `GET /bookings/me`; การซ่อนปุ่มใน UI ไม่ทดแทนการตรวจสิทธิ์ฝั่งบริการ

## การส่งออกรายการ

- ปุ่มส่งออกเรียก `GET /bookings/export.xlsx` ผ่าน client API ที่มี session/authentication เดิมของแอป ไม่ใช้ URL สาธารณะหรือ credential ที่เขียนในหน้าเว็บ
- ส่งตัวกรองสนาม สถานะ คำค้น ภาษา และวันที่เริ่ม/สิ้นสุดที่ผู้ใช้กำหนด; วันที่เริ่มหลังวันที่สิ้นสุดจะแสดงข้อผิดพลาดและปิดปุ่มส่งออก
- API เป็นผู้จำกัดสิทธิ์และสร้าง XLSX; UI ดาวน์โหลดผลตอบกลับแบบ blob และแสดงข้อความสำเร็จ/ผิดพลาดตามภาษาที่เลือก
- ฝั่งเซิร์ฟเวอร์ต้องตรวจ role ADMIN และตรวจช่วงวันที่/ค่า filter ทุกครั้ง ไม่ถือว่า UI เป็น security boundary

## การทดสอบ regression ของ aggregation

รันจากโฟลเดอร์ `frontend`:

```sh
node --test src/lib/dashboard-analytics.test.cjs
```

ชุดทดสอบใช้เวลาคงที่ใน Bangkok timezone และตรวจ:

1. รายวันใช้ชั่วโมง `time_in`, มี bucket ครบ 24 ชั่วโมง และนับรายการจริง
2. รายสัปดาห์เริ่มวันจันทร์ เรียงลำดับ และมี bucket วันที่ไม่มีรายการ
3. รายเดือนมี bucket ครบเดือนและค่า 0 สำหรับวันที่ว่าง
4. รายปีมี bucket เดือนตั้งแต่มกราคมถึงเดือนปัจจุบัน
5. ตัวกรองสนาม ข้อมูลว่าง และ booking date ที่ไม่ถูกต้อง

## ตรวจสอบด้วยมือ

- ตรวจบนจอมือถือและ desktop: แถว KPI, กราฟแท่ง, สรุปสถานะ, toolbar และตารางที่เลื่อนได้ในแนวนอน
- เปลี่ยน Day/Week/Month/Year และสนาม; ตรวจว่าตัวเลขและ bucket เปลี่ยนจากข้อมูลที่โหลดจริง
- ตรวจภาษาไทย (ค่าเริ่มต้น) และอังกฤษในทั้งหน้า ADMIN และผู้ใช้, รวม dialog ยกเลิกและประวัติ
- เปลี่ยน search/status/court/date แล้วส่งออก; เปิด workbook ตรวจว่ารายการสอดคล้องกับตัวกรองและหัวคอลัมน์ตรงกับภาษา
- ยืนยันการปฏิเสธสิทธิ์ export ที่ API เมื่อ session ไม่ใช่ ADMIN และการจัดการ error/empty/loading จาก API
